# Roadmap - Web Intelligence Agent

> Pivot du 2026-10-06 : ce document remplace la roadmap « Findit » (scrapers figés + espace candidat). Le produit devient un agent IA autonome de collecte web. Le cahier des charges fait foi : [CAHIER_DES_CHARGES.md](CAHIER_DES_CHARGES.md) (non recopié ici). États vérifiés sur le dépôt au 2026-10-06, branche `main`, commit `d44dd4b` : chaque ligne renvoie à un fichier lisible.

## 1. Décisions tranchées (2026-10-06)

| Décision              | Choix                                                                                                                                        |
| --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| Espace privé candidat | Supprimé sauf matching/scoring de CV (profil, lettres, candidatures, PDF, `/espace` supprimés ; CV + matching + scoring conservés, agent IA) |

## 2. Ce que le pivot change

**Conservé et réutilisé comme outils de l'agent** : le monorepo (Next.js + NestJS + TypeScript + PostgreSQL/Prisma + Redis/BullMQ + Docker), le scheduler du worker, la recherche web (Brave), la découverte, la lecture de `robots.txt`, le registre de conformité et la garde de budget, la classification (dont la détection d'écoles), la déduplication, le pipeline d'ingestion, les notifications Telegram, le dashboard web.

**Supprimé** : l'espace privé candidat (voir décision), et les connecteurs fixes ATS/job boards deviennent des « outils d'extraction spécialisée » que l'agent peut invoquer, plutôt que des scrapers montés en dur.

**État dans le code** : le run de l'agent (`apps/worker/src/collection/collection-scheduler.service.ts`, `#runAgent`) câble uniquement la recherche Brave (`packages/job-connectors/src/web-search.ts`), le crawler (`packages/crawler/src/crawler.ts`), DeepSeek (`packages/ai/src/deepseek-client.ts`) et la persistance (`packages/persist/src/persist.ts`). Les connecteurs spécialisés (Greenhouse, Lever, Workday, WTTJ, Indeed, HelloWork, France Travail, Workable, Apify) restent dans `packages/job-connectors/src/` mais ne sont pas invoqués par le run.

## 4. V2 (différé)

**Livré** (commits `c2ec0fd` et `10fd3f6`) :

- Mémoire avancée : `packages/agent/src/memory-store.ts` (`hasSeenUrl`, `knownSourcePatterns`) ; types `MemoryKind` (`VISITED_URL`, `ANALYZED_URL`, `SEARCH_QUERY`, `SOURCE_PATTERN`) dans `packages/database/prisma/schema.prisma`.
- Scoring multi-critères : `packages/matching/src/scores.ts` (compétences, lieu, contrat) en complément du score LLM.
- Notifications de run : `packages/notifications/src/agent-run.ts`, `#notifyAgentRun` du worker.
- Analytics : `AgentService.analytics()` dans `apps/api/src/agent/agent.service.ts` et page `apps/web/src/app/dashboard/analytics/page.tsx`.
- Matching/scoring de CV : `packages/matching/src/structure.ts` (`structureCv`), `apps/api/src/matching/`, page `apps/web/src/app/dashboard/matching/page.tsx`.
- Reprise en cascade (CDC §4.7) : moteur borné `packages/orchestrator/src/recovery.ts` ; relecture d'une page vide (`recoverPage`, câblée dans `apps/worker/src/collection/collection-scheduler.service.ts`), extraction déterministe `extractStructuredOffers` (`packages/extract/src/structured.ts`, JSON-LD `JobPosting`) avant le LLM, relance des seuls échecs, abandon journalisé dans `AgentError` avec `retried = true`. Bornes : `maxRecoveries`, `maxAttemptsPerStep`, `maxTotalAttempts`.
- Localisation et dates (qualité d'ingestion) : `resolveLocation` (`packages/job-normalization/src/location.ts`) lit le code postal français et en déduit le département (« 92000 Nanterre, France » → 92), au lieu de refuser l'offre comme vague ; `parsePublishedAt` (`packages/persist/src/persist.ts`) n'accepte qu'une forme ISO, une date non ISO devenant illisible au lieu d'être interprétée à l'américaine.
- Porte déterministe anti-coût (CDC §12) : `packages/extract/src/contract.ts` (`mentionsPerimeterContract`) écarte les pages hors 2xx et n'appelle pas le modèle sur une page qui ne nomme aucun contrat du périmètre. Mesure qui l'a motivée : 127 offres extraites, 101 rejetées faute de contrat, zéro insérée.
- Suivi des tokens et du coût (CDC §12) : `packages/ai/src/usage.ts` (`computeCostMicroUsd`) ; `@findit/ai` lit `usage.input_tokens` / `usage.output_tokens` et cumule (`model.usage()`) ; `packages/orchestrator/src/run-agent.ts` attribue la différence à l'action `EXTRACT` de la page, tentatives refusées comprises, et alimente `AgentAction.costMicroUsd` puis `AgentRun.costMicroUsd`. Le tarif vient de `DEEPSEEK_INPUT_USD_PER_MTOK` / `DEEPSEEK_OUTPUT_USD_PER_MTOK` : sans lui, les tokens restent tracés et le coût reste à zéro. Vérifié sur le réel (11 tokens d'entrée, 1 de sortie, 1 appel).

**Reste à faire** :

- Connecteurs spécialisés en repli (CDC §4.7, étape 3) : la cascade est livrée, mais l'agent n'invoque pas les connecteurs ATS/job boards (`packages/job-connectors/src/`) comme stratégie de secours.
- Planification des recherches par le modèle (CDC §5, première brique) : `packages/orchestrator/src/planner.ts` (`createLlmQueryPlanner`) — le modèle propose les requêtes, schéma Zod, bornées à `maxQueries`, dédupliquées, avec repli automatique sur `generateSearchQueries` si la sortie est invalide, vide ou le modèle en panne. Le plan est consigné (`AgentAction` DISCOVER) avec son coût. Mesure : premier plan générique → crawl sur des agrégateurs en 403 ; prompt corrigé pour commencer par les `site:` → 80 offres extraites en 6 pages pour 3 928 micro-dollars.
- Choix des sources par le modèle (section 5) : `packages/orchestrator/src/selector.ts` ; le tour fait recherche et scoring, puis sélection, puis crawl. Candidates plafonnées à 12, sortie bornée aux URL candidates, repli sur l'ordre du score. Mesure : 3 sélections, 2 025 µ$ dont la moitié en décisions, 2 offres extraites, 0 insérée.
- Redirections résolues avant crawl : `resolveFinalUrl` (`packages/crawler/src/resolve.ts`, HEAD puis GET d'un octet si HEAD est refusé) ; l'agent écarte un alias déjà connu sans le payer. Vérifié sur le réel : quatre adresses Ivalua convergent vers une seule page.
- Clé de mémoire normalisée (`crawlKey`) : casse, `www.`, fragment, slash final et paramètres de suivi (`utm_*`, `gclid`, `fbclid`, `msclkid`, `lever-source`) sont ignorés, **la requête est conservée** — l'effacer faisait collisionner `?page=1` et `?page=2`, donc perdre la seconde page, la mémoire étant sans expiration. Pages non traitées plus jamais inscrites comme visitées ; le crawler reçoit le budget de pages restant au tour.
- Requêtes de source avec le contrat entre guillemets : `planner.ts` (prompt) et `search-queries.ts` (générateur déterministe) citent `"alternance"` / `"stage"`. Mesure Brave : 1 titre du périmètre sur 10 sans guillemets, 6 avec ; `-CDI` inutile (1/10), `stage OR alternance` à 3/10.
- Porte de conformité des sources découvertes : `packages/job-connectors/src/board-access.ts` (`decideDiscoveredSourceAccess`) consulte le registre avant chaque crawl ; un job board connu doit avoir un connecteur actif et autorisé, sinon la source est refusée et le refus journalisé. Vérifié sur le registre réel : LinkedIn et Glassdoor fermés (`NO_CONNECTOR`), Indeed et HelloWork ouverts. Limite : la liste des domaines est bornée à ceux que le registre et `docs/legal-compliance.md` nomment.
- Découverte ciblée sur les pages d'offre : `isAtsBoardListing` (`packages/agent/src/scoring.ts`) distingue la racine d'un board d'une page d'offre ; `run-agent.ts` traverse la première sans l'extraire et n'envoie au modèle que les secondes. Mesure : coût 5 419 → 782 µ$ sur un run borné, mais 1 offre extraite, 0 insérée — les pages atteintes étaient des CDI.
- Boucle décision → outil → résultat → décision (CDC §5) : après chaque tour, `runAgent` transmet au planificateur une observation (requêtes exécutées, sources notées, offres retenues, pages visitées) et appelle `refine` ; un plan relance un tour, `null` arrête. Bornes : `maxQueries` par tour, `maxPlanRounds` (3) et une part du budget de pages par tour (`maxPages / maxPlanRounds`). Mesure : sans cette part, le premier tour prenait les 8 pages et `refine` n'était jamais appelé ; avec elle, le même run a fait 3 tours et le modèle a affiné vers les `site:` ATS (12 866 µ$).
- Boucle d'outils pilotée par le LLM (CDC §5) : partielle. Le modèle choisit les recherches et les révise, mais `packages/orchestrator/src/run-agent.ts` reste une séquence fixe (scoring → crawl → extraction → validation → déduplication → persistance) ; il ne choisit ni le crawl, ni l'extraction, ni l'arrêt.

## 6. Questions ouvertes

- Q-1 : hébergement (worker, API, web) — où faire tourner le cron en continu ? Aucun choix inscrit dans le code.
- Q-2 : authentification (Better Auth vs autre) et multi-utilisateurs — aucun modèle `User` dans `packages/database/prisma/schema.prisma` ; aucune route ni dépendance d'authentification dans `apps/api/src` et `apps/web/src`.
- Q-3 : sources de départ et mode d'accès — le cadrage « 10-20 sources » ne correspond plus à l'annuaire `packages/database/data/employer-directory.csv` (792 entrées, commits `f5f78d5` et `39b2562`) ; le run part d'une recherche Brave puis crawle les pages trouvées. Le mode d'accès retenu par source reste à trancher.
