# Roadmap - Web Intelligence Agent

> Pivot du 2026-10-06 : ce document remplace la roadmap « Findit » (scrapers figés + espace candidat). Le produit devient un agent IA autonome de collecte web. Le cahier des charges fait foi : [CAHIER_DES_CHARGES.md](CAHIER_DES_CHARGES.md) (non recopié ici). États et mesures vérifiés sur le dépôt au 2026-10-07, branche `main`, commit `79d7d30`.

## 1. Décisions tranchées (2026-10-06)

| Décision              | Choix                                                                                                                                        |
| --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| Espace privé candidat | Supprimé sauf matching/scoring de CV (profil, lettres, candidatures, PDF, `/espace` supprimés ; CV + matching + scoring conservés, agent IA) |
| LLM                   | DeepSeek API uniquement (plus d'Ollama local)                                                                                                |
| Périmètre de départ   | MVP V1 (voir section 3)                                                                                                                      |
| Offres d'écoles       | Exclues (écoles, organismes de formation, termes « école »)                                                                                  |
| ORM                   | Prisma (conservé, pas de migration vers Drizzle)                                                                                             |

## 2. Ce que le pivot change

**Conservé et réutilisé comme outils de l'agent** : le monorepo (Next.js + NestJS + TypeScript + PostgreSQL/Prisma + Redis/BullMQ + Docker), le scheduler du worker, la recherche web (Brave), la découverte, la lecture de `robots.txt`, le registre de conformité et la garde de budget, la classification (dont la détection d'écoles), la déduplication, le pipeline d'ingestion, les notifications Telegram, le dashboard web.

**Supprimé** : l'espace privé candidat (voir décision), et les connecteurs fixes ATS/job boards doivent devenir des « outils d'extraction spécialisée » que l'agent pourra invoquer, plutôt que des scrapers montés en dur (non câblés à ce jour, section 4).

**État dans le code** : le run de l'agent (`apps/worker/src/collection/collection-scheduler.service.ts`, `#runAgent`) câble uniquement la recherche Brave (`packages/job-connectors/src/web-search.ts`), le crawler (`packages/crawler/src/crawler.ts`), DeepSeek (`packages/ai/src/deepseek-client.ts`) et la persistance (`packages/persist/src/persist.ts`). Les connecteurs spécialisés restent dans `packages/job-connectors/src/` mais ne sont pas invoqués par ce run. En revanche, le cycle séparé des boards scrapés (`apps/worker/src/collection/scraped-sources.ts`) exécute WTTJ, HelloWork et Indeed ; il est allumé par défaut (`SCRAPED_SOURCES_ENABLED`, `packages/config/src/env.ts`) et planifié une fois par jour (`SCRAPED_COLLECTION_CRON`).

## 4. V2

**Livré** (commits `c2ec0fd` et `10fd3f6` pour les briques initiales, puis commits ultérieurs dont `9535df9`, `2eca4ae`, `84269b0`, `c7ab98b`) :

- Mémoire avancée : `packages/agent/src/memory-store.ts` (`hasSeenUrl`, `knownSourcePatterns`) ; types `MemoryKind` dans `packages/database/prisma/schema.prisma`.
- Scoring multi-critères : `packages/matching/src/scores.ts` (compétences, lieu, contrat) en complément du score LLM.
- Notifications de run : `packages/notifications/src/agent-run.ts`, `#notifyAgentRun` du worker.
- Analytics : `AgentService.analytics()` dans `apps/api/src/agent/agent.service.ts` et page `apps/web/src/app/dashboard/analytics/page.tsx`.
- Matching CV et son suivi : `packages/matching/src/structure.ts` (`structureCv`) et `apps/api/src/matching/` ; table `ModelCall` (migration `20261007020000_model_calls`) écrite par `matching.service.ts`, coût exposé par `GET /api/agent/analytics` (`matchingCost`) et affiché dans le dashboard ; table `MatchingRun` (migration `20261007030000_matching_runs`), rétention `MATCHING_RETENTION_HOURS` (72 h, purge à chaque écriture), `GET /api/matching/history` et `GET /api/matching/history/:id`, section « Matchings passés » de la page Matching.
- Reprise bornée (brique partielle du CDC §4.7) : moteur `packages/orchestrator/src/recovery.ts` (`runRecovery`, bornes `maxAttemptsPerStep`/`maxTotalAttempts`), relecture d'une page vide (`recoverPage`, `maxRecoveries`), extraction déterministe `extractStructuredOffers` (`packages/extract/src/structured.ts`, JSON-LD `JobPosting`) avant le LLM, abandon journalisé dans `AgentError.retried`.
- Localisation et dates : `resolveLocation` (`packages/job-normalization/src/location.ts`) déduit le département du code postal ; `parsePublishedAt` (`packages/persist/src/persist.ts`) n'accepte qu'une forme ISO.
- Porte anti-coût (CDC §12) : `packages/extract/src/contract.ts` (`mentionsPerimeterContract`) écarte les pages hors 2xx et n'appelle pas le modèle sur une page qui ne nomme aucun contrat du périmètre.
- Suivi des tokens et du coût (CDC §12) : `packages/ai/src/usage.ts` (`computeCostMicroUsd`), `model.usage()`, puis `AgentAction.costMicroUsd` et `AgentRun.costMicroUsd`.
- Recherche et sélection par le modèle (CDC §5) : `packages/orchestrator/src/planner.ts` (`createLlmQueryPlanner`, `refine`) et `packages/orchestrator/src/selector.ts`, bornés par `maxQueries`, `maxPlanRounds` et une part du budget de pages par tour.
- Détection d'écoles renforcée : liste citée d'employeurs-écoles et formulations décisives dans `packages/extract/src/school.ts` ; une école écartée laisse son nom dans le motif de rejet (`ingest.ts`, `persist.ts`).
- Porte de conformité des sources découvertes : `decideDiscoveredSourceAccess` (`packages/job-connectors/src/board-access.ts`) consulte le registre avant chaque crawl ; un job board connu sans connecteur actif est refusé et le refus journalisé. Limite : la liste des domaines couvre ceux que le registre et `docs/legal-compliance.md` nomment.
- Registre : Workable n'est pas enregistrable (collecte par requête, pas par jeton) et un hôte inconnu relève du registre dynamique gouverné par `robots.txt` (`register-discovery.ts`, `board-access.ts`).

**Reste à faire** :

- Connecteurs spécialisés en repli (CDC §4.7, étape 3) : l'agent n'invoque pas les connecteurs ATS/job boards (`packages/job-connectors/src/`) comme stratégie de secours.
- Boucle d'outils pilotée par le LLM (CDC §5) : partielle. Le modèle choisit les recherches et les révise, mais `packages/orchestrator/src/run-agent.ts` reste une séquence fixe (scoring → crawl → extraction → validation → déduplication → persistance) ; il ne choisit ni le crawl, ni l'extraction, ni l'arrêt.
- Dettes : `.claude/` (~100 Mo) suivi par git ; clés mortes dans `.env` (absentes du schéma `env.ts` et de tout code, dont `SCRAPEGRAPH_API_KEY` et `DATABASE_URL_OWNER`) ; couverture des contrôleurs de l'API faible (20-50 %) ; paquet `packages/shared` sans test ; règle de date recopiée dans `packages/job-connectors/src/linkedin.ts` au lieu d'`endOfDayIfDateOnly` (`packages/shared/src/job-scope.ts`), le paquet ne dépendant pas de `@findit/shared` ; `canonicalAtsHost` (`packages/job-connectors/src/ats-hosts.ts`) ne couvre que Greenhouse.

## 7. Questions ouvertes

- Q-2 : authentification multi-utilisateurs — l'accès actuel est mono-utilisateur (mot de passe unique + cookie signé, `apps/web/src/app/api/session/route.ts`) ; le périmètre multi-utilisateurs reste à trancher.

Le mode d'accès retenu par source reste à trancher.
