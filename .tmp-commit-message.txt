feat(espace personnel): page /moi, profil stocke et acces par mot de passe

Findit sert d'abord son utilisateur : le dashboard s'appelait Administration, il
est repris. La page /moi montre le profil (nom, titre, ville, contact), les
competences, les langues, les experiences, les liens, le CV et les matchings
passes, editables par action serveur.

Table Profile singleton (migration 20261007043000_profile, appliquee avec la
connexion proprietaire), GET et PUT /api/profile gardes par x-internal-key
compare en timingSafeEqual : 401 sans cle, 400 sur corps invalide, jamais 404.

Acces par mot de passe unique echange contre un cookie signe HMAC-SHA-256. La
signature engage aussi le mot de passe, donc le changer revoque les sessions
ouvertes. Sans PROFILE_PASSWORD, le site public tourne et /moi annonce que
l'espace n'est pas configure, sans boucle de redirection.

Navigation reorganisee : Mon espace puis Exploitation sur l'accueil, barre
laterale renommee (Offres, Sources, Crawls, Agent, Matching, Analytics, Logs,
Configuration).

middleware.ts devient proxy.ts (convention Next 16) et allowedDevOrigins corrige
un piege paye : avec le serveur de developpement sur 0.0.0.0, passer par
127.0.0.1 faisait bloquer les ressources de developpement et le client ne
s'hydratait plus, alors que la production n'etait pas touchee.
